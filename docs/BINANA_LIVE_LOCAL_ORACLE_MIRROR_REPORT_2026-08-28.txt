Scope and safety boundary
-------------------------
This change mirrors only applicable non-core hardening from the independently
validated TestNet package. It does not change strategy signals, indicators,
entry/exit logic, position sizing, protected legacy execution logic, or the
V19.1 Sharia decision engine/rulebook. It does not configure credentials,
deploy to a host, enable LIVE-money execution, or place an order.

Implemented non-core changes
----------------------------
1. Added a guarded Sharia screener entrypoint so a missing or unusable local
   registry is explicit and fail-closed instead of appearing healthy.
2. Added owner/operator source-review helpers and tests without permitting
   discovered records to self-authorise trading.
3. Strengthened source-registry seeding, URL/identity checks, provider request
   budgets, public Binance HTTP handling, and regression coverage.
4. Expanded the Telegram broker's read-only status and operator information
   surfaces without exposing secrets or granting it order ownership.
5. Added validation-environment, pair-file, Oracle capacity, provider-budget,
   and Sharia operator regression tests.
6. Corrected LIVE deployment namespaces and retained LIVE's production public
   metadata endpoint while keeping execution in simulation by default.
7. Enforced a two-CPU Oracle capacity floor and ARM64 default; AMD64 requires an
   explicit reviewed override for temporary AWS experiments.
8. Repaired the scheduled Binance contract-drift Action pin and retained
   read-only contract checking.
9. Updated operator documentation for the LIVE paths, API readiness, Telegram,
   backups, rollback, and local Sharia source review.
